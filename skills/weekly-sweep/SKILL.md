# Weekly Sweep Skill

每周日晚执行的系统维护扫描。30 分钟内完成全 baseline 健康检查。

## 触发条件

- 定时任务每周日 21:00 触发
- 用户手动说"weekly sweep"、"周扫描"、"维护扫描"

## 执行步骤

### Phase 1：过期检测

1. 读取 `03_baseline/INDEX.md` 获取全部 baseline 文件
2. 检查每个文件的 `last_updated` 是否超过其 tier 标准：
   - T1: >7 天 = 过期
   - T2: >30 天 = 过期
   - T3: >90 天 = 过期
3. 生成过期文件排序列表（按影响度排序）

### Phase 2：新增原料检测

4. 扫描 `01_raw/` 目录，找出上周新增的文件
5. 判断哪些新原料可能影响现有 baseline（按文件名和路径匹配）
6. 标记"有新原料但 baseline 尚未更新"的条目

### Phase 3：质量检查

7. 统计所有 `[需补全]` 标记，按存在天数排序
8. 查找 `[判断: AI, low]` 或 `[判断: AI, speculative]`，建议补强
9. 跨文件一致性：同一事实在不同文件中的描述是否一致

### Phase 4：Proposal 清理

10. 检查 `99_workspace/baseline_proposals/` 中超过 14 天未处理的 draft
11. 建议用户批准、修改或关闭

## 配置

```json
{
  "name": "weekly-sweep",
  "schedule": "0 21 * * 0",
  "description": "每周日全 baseline 维护扫描"
}
```

## 注意事项

- Sweep 只读不写——它生成报告但不自动修复问题
- 如果发现严重矛盾（同一事实两个文件说法相反），标为 red flag
- 输出应控制在 5 分钟可读完的长度
